# 04. The engine fork in `crates/`

Baseline `7a2bc95`. Evidence for summary finding F7.

## What was done

Commit `ed84001` copied the upstream engine at commit `ddef371` (the
revision the port was already pinned to) into `crates/` as 21 workspace
crates and renamed it. `docs/decisions.md` (D-engine) records the rename
table and the reasons. `LICENSE` keeps the upstream MIT text as a
third-party notice. Commit `7a2bc95` turned off the engine's `log`
feature by default (see the summary).

| Item | Value |
|---|---|
| Crates | 21 (`mineflayer-engine` facade, 15 library crates, 5 proc-macro crates) |
| Rust lines | 122,646 |

The rename is token-based. Game data that contains the word (the azalea
and flowering azalea blocks, their sound events, the
`AZALEA_GROWS_ON`/`AZALEA_ROOT_REPLACEABLE`/`SUPPORTS_AZALEA` tags, and
the en_us strings) was left alone, because it is Minecraft data, not
project branding.

## Open ownership questions

### The generator is upstream only

The registry, block, item component, entity metadata, language, and
packet files in the engine are generated by Python scripts in upstream's
`codegen/` (24 files, present in the git-ignored `ref/azalea/codegen`).
They were not copied. The next Minecraft version needs those scripts.
There are two options: copy `codegen/` into the repository and keep it
working against our crate names, or merge upstream's regenerated output
through the upgrade procedure and never run the generator here. The
second option is less work now and more work at each upgrade. Decide
before the first upgrade, and record the decision.

### Code compiled only to be switched off

`src/client_app.rs` copies upstream's bootstrap, which adds
`DefaultSwarmPlugins` (the swarm module is 1,269 lines). The port never
creates a swarm. The default plugin set also includes auto-reconnect
(135 lines), which `connect` disables with `Duration::MAX`, and
`auto_respawn`, `accept_resource_packs`, and `auto_tool`, which the port
either reimplements (`src/tool.rs`) or does not use. After the plugin
hook in `01_engine_boundary.md` (P3), measure which modules the port
reaches and remove the rest from the engine. Removing the swarm alone
also removes its builder, its event loop, and its prelude.

### Versions and publishing

`[workspace.package] version` is `0.16.0+mc26.1`, upstream's version
line, so the build metadata still names the Minecraft version. The port
is `0.2.0`. All 22 crate names (the 21 engine crates and `mineflayer`)
returned 404 from the crates.io API on 2026-10-16, so they are free
today. Publishing the port means publishing 21 more crates first, since
path dependencies must be published. If publishing is not planned, mark
the engine crates `publish = false` so nobody publishes them by
accident; that also blocks publishing `mineflayer` until the decision
changes.

### Lints and docs

`cargo clippy --all-targets -- -D warnings` at the root lints every
workspace member, so the gate already holds the engine to zero clippy
warnings under the pinned toolchain. The doc step runs
`cargo doc --no-deps` for the root only; engine rustdoc warnings are not
gated. Engine debug builds print a warning from the pathfinder when
`OPT_LEVEL` is 0; a `[profile.dev.package."mineflayer-*"] opt-level = 1`
entry would remove the warning and speed up the live tests, at a cost in
compile time.

### Upstream merges

`docs/version_upgrade.md` now describes the upgrade as a diff from the
base commit to the new upstream revision, renamed with the D-engine
table, then applied to `crates/`. Every local engine change (the ones
above, and the proposals in `01_engine_boundary.md`) makes that merge
harder. Keep a short list of local engine changes in
`docs/decisions.md` next to D-engine, so a merge can check each one.

## Build cost

`target/` is 31 GB after this session's builds (the previous plan's F3
measured 5.8 GB after a clean). The gate now builds the engine crates
twice, once as the port uses them and once with `log` for their own
tests. CI uses `Swatinem/rust-cache`, which prunes to dependency
artifacts; local machines should `cargo clean` after large changes.
